Approach

Metadata-driven · User-in-control · Phased workflow

Metadata-Driven Validation

  • Reads EUSFA Salesforce DX metadata from local clone (EUSFA_SFDX_REPO_PATH)
  • Picklist values, field types, required fields, and template configs from Template_Config__mdt
  • Session metadata version lock — warns if metadata changes mid-session
  • Git fetch/pull panel for approved metadata updates

User Stays in Control

  • Safe changes proposed — never auto-applied without approval
  • Never invents Salesforce IDs or guesses lookup values
  • Blocking issues must be resolved or acknowledged before Tool-Ready download
  • Dual download: Tool-Ready CSV vs Review CSV for audit

Design principle: The Copilot prepares and explains — it does not replace Workbench or the Data Import Tool.

Decisions

Key Decisions & Tradeoffs

No Auto-Guessing Picklists

Invalid picklist values surface for manual correction with valid API values shown. Prevents silent mis-mapping of business labels to wrong API values.

Implemented

Dual Download Model

Tool-Ready CSV — gated until all blocking issues resolved.
Review CSV — always available with change log for audit, even when not upload-ready.

Implemented

Local Metadata vs Live Salesforce

Validation uses local SFDX clone (fast, offline-capable). Live record existence check available for Workbench Update — no invented IDs.

Tradeoff: metadata refresh is manual

Workbench-Richer Than DIT (Today)

Picklist correction UI, header mapping confirmation, and unified download gate are Workbench-first. DIT path covers template comparison, dates, and row validation — picklist UI on roadmap.

Known gap

Detect-Only for Some Issues

Scientific notation, duplicate keys, and numeric format issues are flagged as blocking manual review — not auto-corrected (by design, to preserve data integrity).

Dependency Rules — Stub

Cross-object dependencies (e.g., load Pepsi products before competitors) not yet configured. Upload order guidance provides human-readable prerequisites instead.

Q&A · 5 min

Anticipated Questions

Does this replace Workbench or DIT?
No. The Copilot prepares and validates CSVs before you upload via Workbench or DIT. It reduces failures; the actual upload still happens in Salesforce.
Does it connect to live Salesforce?
Validation uses your local EUSFA SFDX metadata clone (read-only). Workbench Update flows can optionally check record existence live. No data is written to Salesforce.
What if metadata is out of date?
The app has a metadata panel with fetch/pull controls. Sessions lock to the metadata version at upload time and warn if it changes mid-session.
Can it fix all errors automatically?
Safe fixes (whitespace trim, date conversion, header rename) are proposed for approval. Blocking issues like scientific notation, duplicates, and invalid picklists require manual action — by design.
Is it ready for production use?
Core Workbench and DIT flows are implemented with 140+ tests. Known gaps (DIT picklist UI, dependency rules) are documented with a clear roadmap. Suitable for pilot with ops teams now.
How do we run it?
pip install -r requirements.txt then streamlit run app.py. Requires Python 3.11+ and a local EUSFA SFDX clone.
